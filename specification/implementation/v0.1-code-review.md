## Findings in detail

### 1 · 🟠 Snapshot aliasing (sim/save.gd)

**Scenario:** `var snap := SimSave.snapshot(sim)` followed by `var fork := SimSave.restore(snap)` — no file in between. `snapshot()` builds pair arrays with `world.objects[cell]` / `world.patches[patch_id]` directly, so the restored sim's dictionaries are the *same instances*. The first `spawner` regeneration that does `patch["reserve"] = …` mutates both sims; their hashes stay silently entangled. The shipped file path is safe only because `store_var` serializes immediately — the seam's contract ("a snapshot is the full sim state") is violated the moment a caller holds one. v1's arena forks sims exactly this way.
**Fix:** deep-copy in `snapshot()` (`duplicate(true)` for object/patch dicts, `duplicate()` for the cells array and packed layers) — the snapshot becomes immutable-by-construction. Regression: an in-memory round trip, then step only the original and assert the restored copy's hash is unaffected.

### 2 · 🟠 Dawn re-save after a boundary resume (sim/sim.gd, sim/save.gd, tools/run_sim.gd)

**Scenario:** the dawn edge saves *before* phases (correct — boundary state), but a run killed right at that boundary (the shutdown save lands at tick 1060) resumes, and `step()` sees `is_dawn_tick()` true again → a second autosave of the same boundary. `saves_written` is also session-local (resets to 0 on restore), so the resumed run's stats trace reads `saves 0` where the uninterrupted twin reads `saves 1` — `tests/test_headless.gd` masked exactly this with a `replace()` on the saves field instead of surfacing it.
**Fix:** persist `saves_written` and a `last_autosave_tick` in the snapshot; the dawn edge skips when `last_autosave_tick == clock.tick`. Neither field enters `state_hash()` (they are I/O metadata and never influence sim evolution). Regression: kill-at-dawn-boundary resume → stats lines equal the uninterrupted run's *including* the saves field; the `replace()` hack removed.

### 3 · 🟠 Fresh-clone failure of the run wrapper (scripts/run_headless.sh)

**Scenario (reproduced):** `rm -rf .godot && scripts/run_headless.sh --ticks=5` → `Parse Error: Could not find type "Sim"` ×4, no run — and exit code 0, so even a script would not notice. The global class cache (`.godot/global_script_class_cache.cfg`) does not exist on a fresh clone, and the wrapper, unlike `scripts/test.sh`, never imports.
**Fix:** the same import-once guard `test.sh` uses, triggered when `.godot/` is missing. Verified by deleting `.godot` and running the wrapper again.

### 4 · 🟡 `*.import` ignored (deferred → v0.2)

Godot 4 `.import` metadata should be committed once real imported assets exist; v0.1 has none, v0.2 brings the PNG creature sheets whose import settings (filtering, mipmaps) matter. Remove the rule in the issue that copies the sheets into `res://art/`.

### 5 · 🟡 Engine-version-coupled hashing (deferred → v3)

`hash()`/`String.hash()` are platform-independent but not guaranteed stable across engine releases. Within one pinned engine (CI + VERSIONS pin 4.7.2) every determinism promise holds; cross-version replay is v3's concern — note it there rather than hand-rolling a hasher now.

### 6 · 🟡 Restore trusts the snapshot (deferred → v1)

After the `format_version` gate, `restore()` indexes fields without validation; a truncated or hand-edited file crashes with a raw error instead of the save-refusal message. Fine for a v0 prototype with a single local autosave; fold shape validation into v1's robustness work.

## Fixes applied

**1 · ddee0d1 — `fix(sim): snapshots deep-copy every mutable layer`**
`SimSave.snapshot()` duplicates object/agent/patch dictionaries and the packed layers; `restore()` duplicates everything incoming, so several restores from one snapshot are independent of it and of each other. *Regression:* `test_save.gd::test_in_memory_snapshot_is_isolated` — fork a sim in memory, mutate a patch dict and a terrain byte on the original and step it 250 ticks; the fork's hash, a second fork, and fork-vs-fork independence all hold. *Verified:* suite 42/42 at the commit.

**2 · 6064227 — `fix(sim): dawn-save count persists; no duplicate save on boundary resume`**
`saves_written` (session-local) became `dawn_saves` + `last_autosave_tick`, both persisted in the snapshot and restored; exit saves are not counted; a dawn save stamps itself *before* writing, so the dawn file already knows its dawn happened; the dawn edge skips when the stamp equals the current tick. Neither field enters `state_hash()` — they are I/O metadata and never influence sim evolution. *Regression:* `test_headless.gd::test_resume_at_dawn_boundary_no_duplicate_save` (kill mid-tick-1060 right after the dawn write → resume → `dawn_saves` stays 1, stats line and hash equal the uninterrupted run) plus the `replace()` workaround removed from the resume test — it now demands letter-equality including the saves field. *Verified:* suite 43/43 at the commit.
**Architecture impact:** the snapshot gained two metadata fields (`dawn_saves`, `last_autosave_tick`). ARCHITECTURE §Saves describes the snapshot content generically (clock, layers, RNG states, …) and stays accurate; `format_version` stays 1 — the phase has never been released, so no shipped format existed to migrate. The stats `saves` field now means *dawn autosaves this world has written* (exit saves excluded) — which is what makes a resumed trace equal an uninterrupted one.

**3 · af5d6ba — `fix(tools): run_headless.sh imports once on a fresh checkout`**
The wrapper runs the same one-time `--import` the test gate uses when `.godot/` is missing. *Regression:* shell-level — reproduced the failure (`rm -rf .godot` → four `Could not find type "Sim"` parse errors, exit 0), applied the guard, re-ran on a wiped cache: full run, stats, autosave. The suite itself keeps covering the import path via `scripts/test.sh`. *Verified:* suite 43/43 at the commit.
