# v0.1 — GitHub Issues

Issues for phase **v0.1 — Headless simulation and world generator** (version **v0 — Prototype "First Night"**),
derived from the per-phase Tasks in [ROADMAP.md](../ROADMAP.md) (§v0.1) and the
contracts in [ARCHITECTURE.md](../ARCHITECTURE.md) (§World model, §Time and the tick, §Determinism and replay, §Saves, §Contracts, §Testing).
This file is scoped to a single phase; IDs start the global sequence
(**MYRMEX-001…006** — both GitHub and local sources are empty, so 001 is genuinely first).

The phase stands up `res://sim/` as pure data — layer arrays, named RNG streams, the clock, the world generator with highland massifs, the seven-phase tick loop with environment dynamics, object-free serialization with a single-file autosave — plus the headless entry point and the canonical test gate (`scripts/test.sh`, gdUnit4). Everything later builds on these seams, so four contracts get pinned here: the terrain/structure cell layers, the RNG streams, the tick phase order, and the save format.

### MYRMEX-002 — Named RNG streams and the day-cycle clock

**Description:**
The determinism core: every random draw flows through named streams derived from one master seed, and the clock turns a tick counter into day/phase state. Touches `res://sim/rng.gd`, `res://sim/clock.gd`, `res://tests`.

**What needs to be done:**
- `rng.gd`: streams `worldgen`, `spawner`, `combat`, `strategy`, `interventions`, each a `RandomNumberGenerator` seeded from `hash(master_seed, stream_name)`; accessor `stream(name)`; state export/import per stream (for saves); unknown stream name is a hard error.
- `clock.gd`: tick counter, day number, phase (`DAY`/`DUSK`/`NIGHT`/`DAWN`) computed from the 600/60/400/60 cycle in `sim_params`, `is_dawn_tick()` edge detection for the autosave trigger, ticks-to-next-phase query; pause/single-step/speed multipliers live in the runner, not here — the clock only counts ticks it is given.
- No `Node`, no scene, no wall clock anywhere in either file.

**Dependencies:** MYRMEX-001

**Expected result:**
Deterministic named streams and an exact day-cycle clock, both pure data.

**Acceptance criteria:**
- [ ] **Contract test:** stream independence — draws from `spawner` never shift `combat`'s sequence; same master seed → identical sequences per stream; export/import of stream state resumes the sequence exactly.
- [ ] **Unit test:** phase boundaries land exactly at ticks 600/660/1060/1120 with day rollover; `is_dawn_tick()` fires once per day.
- [ ] **Unit test:** with the **LLM mocked by default** rule untouched (no provider code in this phase).
- [ ] Ties to DoD: two constructions from one seed produce identical draw sequences.

### MYRMEX-003 — World model layers and the seeded generator

**Description:**
The cell layers exactly as ARCHITECTURE §World model pins them, and the generator that fills them from a seed — including highland massifs and the start guarantees. Touches `res://sim/world.gd`, `res://sim/worldgen.gd`, `res://tests`.

**What needs to be done:**
- `world.gd`: `PackedByteArray` terrain (`GROUND`, `WATER`, `HIGHLAND`, `WALL` — the last three impassable), `PackedByteArray` structures (`NONE`, `NEST_WALL`, `PAVEMENT`, `STORAGE_FOOD`, `STORAGE_RES`, `QUEEN_CHAMBER`), sparse `Dictionary` objects (`FOOD{units}`, `RESOURCE{patch_id}`, `PILE{type, units}` — one per cell), sparse agents dictionary (empty this phase), per-nest `known` `PackedByteArray`; cell indexing `x + y*size`; passability query (terrain + structure).
- `worldgen.gd`, all randomness via the `worldgen` stream: `FastNoiseLite` water and rock fields; **highland massifs** as ellipse blobs + noise; 2–3 cellular-automaton smoothing passes; largest connected ground region by flood fill; start point at its centre, cleared to radius 12; `QUEEN_CHAMBER` placed free on the cell **north** of the start cell; patch registry — N patches of 3–12 cells with one shared reserve (10–60) each; starting food items (1–5 units, denser near the start).
- Start guarantees enforced, regenerating with a derived sub-seed when violated: ≥2 patches and ~20 food units within 30 cells; the start region **not enclosed** by massifs (flood fill from start reaches a minimum area).
- Float noise is allowed here only (worldgen runs once; output stored in the byte arrays) per §Determinism and replay.

**Dependencies:** MYRMEX-002

**Expected result:**
`Worldgen.generate(seed, params)` returns a fully populated, guarantee-satisfying world, identically for identical seeds.

**Acceptance criteria:**
- [ ] **Contract test:** the cell-layer shapes and enum values pinned (terrain and structure byte values, object dictionary shapes).
- [ ] **Unit test:** guarantees hold across a batch of seeds — start clearing, ≥2 patches, ~20 food within 30 cells, start-region connectivity with highland present.
- [ ] **Unit test:** generation determinism — same seed → identical terrain/structure/object hash; different seeds differ.
- [ ] Ties to DoD: the generated world is the state the headless run prints and saves.

### MYRMEX-004 — The seven-phase tick loop and environment dynamics

**Description:**
The simulation aggregate stepping the fixed seven-phase tick, with the environment phase alive: food spawning and patch regeneration (world-wide in v0 — no chunks). Agent/combat/knowledge phases are explicit no-ops this phase. Touches `res://sim/sim.gd` (new — one-line addition to ARCHITECTURE §Repository layout rides along), `res://sim/spawner.gd`, `res://tests`.

**What needs to be done:**
- `sim.gd`: owns world + clock + rng + spawner + (later) save; `step()` runs phases in the invariant order — 1 environment, 2 queen planning (no-op), 3 myrmeks (no-op), 4 predators (no-op), 5 combat (no-op), 6 knowledge (no-op), 7 render sync (absent headless) — with a phase-trace hook for the order test.
- `spawner.gd`, all randomness via the `spawner` stream: every `T_food` ticks each *world region* rolls `p_food` for a 1–3 cell food cluster of 1–5 units (v0: the whole map is one active region); a depleted patch regains a reserve after `T_res` ticks.
- Add `sim.gd` to ARCHITECTURE §Repository layout (docs-only line; no seam change).

**Dependencies:** MYRMEX-003

**Expected result:**
`sim.step()` advances the world deterministically; food appears and patches regenerate on the documented cadence.

**Acceptance criteria:**
- [ ] **Contract test:** the tick phase order — the trace of one `step()` is exactly the seven phases in ARCHITECTURE §Time and the tick.
- [ ] **Unit test:** spawn cadence honours `T_food`/`p_food` (statistically over a run window) and `T_res` regeneration; all draws from the `spawner` stream only.
- [ ] **Unit test:** N ticks from one seed → identical state hash across two sims (DoD determinism).
- [ ] Docs: `sim.gd` line present in ARCHITECTURE §Repository layout.

### MYRMEX-005 — Object-free serialization and the single-file autosave

**Description:**
Saving is serialization of pure data — plain types only, never `bytes_to_var_with_objects` — into one compressed autosave with a JSON sidecar header; dawn and shutdown write it, launch resumes from it. Touches `res://sim/save.gd`, `res://tests`.

**What needs to be done:**
- `save.gd`: snapshot `{format_version, seed, params snapshot, clock state, terrain/structures/known arrays, objects, patch registry, agents (empty), rng stream states, outcome: "running"}` — **plain types only** (numbers, strings, arrays, dictionaries, packed arrays); `var_to_bytes` into `FileAccess.open_compressed` at `user://autosave.save`; JSON header beside it (`version, seed, day, population, date, outcome`).
- Load path with `bytes_to_var` (**never** `*_with_objects`); resume reconstructs sim state exactly; a header whose `format_version` is older than current → honest refusal.
- Triggers wired in `sim.gd`: on `is_dawn_tick()`; an explicit `save_now()` for the runner's shutdown path.
- v0 simplification per ROADMAP: one file, no rotation, no slots.

**Dependencies:** MYRMEX-004

**Expected result:**
Kill at any tick after a dawn save, relaunch, and the run continues bit-identically with the uninterrupted one.

**Acceptance criteria:**
- [ ] **Contract test:** the save round-trip — save at tick T, load, run both copies to T+N → identical state hashes; and the serialized tree contains plain types only (recursive type scan).
- [ ] **Unit test:** dawn trigger writes exactly once per day; the JSON header carries the documented fields incl. `outcome`.
- [ ] **Unit test:** an older `format_version` refuses with a clear error, never a silent migration.
- [ ] Ties to DoD: relaunch-resumes-identically is the test above.

### MYRMEX-006 — Headless entry point, stats and the determinism harness

**Description:**
The runnable phase deliverable: `godot --headless` boots a seeded sim, prints evolving stats, autosaves, resumes — plus the state-hash flag the determinism tests and later the arena lean on. Touches `res://tools/run_sim.gd`, `scripts/run_headless.sh`, `res://tests`.

**What needs to be done:**
- `res://tools/run_sim.gd` (a `SceneTree` script): args `--seed=`, `--ticks=`, `--size=`, `--new` (ignore autosave), `--hash` (print the final state hash), `--stats-every=` (default 100); resumes from `user://autosave.save` when present and `--new` absent; prints `day/tick/phase · food items · patch reserves · saves` lines; saves on dawn and before exit.
- `scripts/run_headless.sh` — thin wrapper (`godot --headless --script res://tools/run_sim.gd -- …`).
- The DoD checks as tests, in-process where possible: two sims from one seed → identical stats trace and final hash; save-interrupt-resume equals uninterrupted.

**Dependencies:** MYRMEX-005

**Expected result:**
`scripts/run_headless.sh --seed=42 --ticks=3000` prints a living world's stats twice identically, and a killed run resumes exactly.

**Acceptance criteria:**
- [ ] Headless run prints evolving stats and exits cleanly; `--hash` output is stable per seed.
- [ ] **Unit test:** two runs, one seed → identical output (the DoD line, automated).
- [ ] **Unit test:** interrupt-and-resume equals uninterrupted continuation (via save/load harness).
- [ ] The whole suite stays green via `scripts/test.sh`.
